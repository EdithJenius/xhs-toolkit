# 电商内容工作流

## 1. 收集素材

用 Agent-Reach 或已登录的 MCP 搜索相关主题，记录笔记链接、观察日期、标题结构、互动信号与用户提问。数据不足时说明样本范围，不将点赞量直接当成销量。

提示词示例：

> 围绕“桌面收纳”查找近期内容，整理用户反复提到的 5 个问题。每个结论附来源链接和采集日期，并区分直接观察与推断。

## 2. 写出内容

结合自己的商品事实形成选题。没有验证的材质、尺寸、价格、认证和效果不写成事实。

> 根据这些素材和我提供的商品规格，提出 3 个内容方向。每个方向包含目标读者、标题、三段正文、配图建议和需要补充的证据。

## 3. 选择出图方式

需要插画、场景或多页视觉叙事时使用图文分镜技能；需要清晰文字、表格和统一排版时使用社交卡片技能。单篇内容先选一种方式，避免多个渲染流程互相覆盖。

> 将已确认的文案拆为 5 张卡片：封面、问题、方案、细节、总结。只使用提供的商品事实和授权素材，先给逐页文案与版式，再生成图片。

## 4. 发布与复盘

在本地检查文字、图片顺序和商品信息，再进入已授权的发布流程。保留上游的发布确认与账号保护步骤；发布后查看笔记页面确认实际结果。

复盘时对照同一观察窗口记录曝光、互动、问题与下一次调整。账号分析和登录态保留在本地运行/知识库目录，不随工具源码提交到 GitHub。

## 文件组织建议

```text
本地任务目录/
  brief.md       商品事实、目标读者、素材来源
  draft.md       标题、正文、标签
  images/        按顺序保存的图片
  review.md      检查结果与后续复盘
```

这是建议的工作目录，不是强制的数据格式；可以直接沿用现有项目结构。
